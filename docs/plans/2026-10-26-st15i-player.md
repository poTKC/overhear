# ST15i Player Implementation Plan

> **For Claude:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Build an Android 4.1+ app that turns the Xperia mini ST15i into a standalone Spotify Connect speaker with a now-playing screen, controls and a queue view, driven by Spotify's official Soloist binary.

**Architecture:** The app downloads Soloist (arm32) from Spotify's CDN and runs it under a bundled Debian glibc. A replacement `libpulse.so.0` (fakepulse) forwards PCM over an abstract unix socket to the app, which plays it with AudioTrack. The UI talks to Soloist's local WebSocket API. Design: `docs/plans/2026-10-26-st15i-player-design.md`.

**Tech Stack:** Java 8 source level against `android.jar` (minSdk 16, targetSdk 18), no Gradle (javac + d8 + aapt2 + zipalign + apksigner from build-tools 36.0.0). C11 via `zig cc` for fakepulse. Go 1.27 for the static `st15i-fetch` helper. JUnit 4 plus org.json on the JVM for unit tests.

**Conventions:**
- Device serial: `BX902VYGD7` (only device). Commands assume `adb` reaches it.
- Package: `jp.tkc.st15iplayer`.
- Screenshots: `adb shell screencap /sdcard/s.raw`, then convert with `tools/raw2png.py` (PNG mode returns a black frame on this ROM).
- Soloist API key: on the Mac it lives in `~/.soloist_key`. Never print it, and never commit it.
- Commit after every task, ending messages with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

### Task 2: fakepulse into the repo, with a host test harness

**Files:**
- Create: `native/fakepulse.c` (copied from the scratchpad prototype), `native/build.sh`, `native/test/harness.c`, `native/test/run.sh`, `native/include/` (vendored pulse headers from Debian `libpulse-dev` 17.0, LGPL-2.1)

**Step 1: Write the failing harness.** `harness.c` dlopens `./libpulse.so.0` built for the host (macOS arm64) and replays Soloist's call order. It asserts:
- the context is CONNECTING right after `pa_context_connect` and reaches READY after waiting
- the stream reaches READY, and `pa_stream_writable_size` is greater than 0 before any write
- after writing 1 s of float silence plus a 1 kHz tone in file mode, the output file holds about 1 s of s16 frames, written in real time (±10%)
- after cork and a 300 ms sleep, the file does not grow
- flush makes `writable_size` return to the maximum

**Step 2:** Run `native/test/run.sh`. Expected: it fails, because the host build target does not exist yet.

**Step 3:** Make `native/build.sh` build two targets:
- `build/native/host/libpulse.so.0` with `zig cc -target aarch64-macos -shared`
- `build/native/armhf/libpulse.so.0` with `zig cc -target arm-linux-gnueabihf.2.38 -mcpu=cortex_a8 -shared -fPIC -O2 -fvisibility=hidden -Wl,-soname,libpulse.so.0`

Guard the abstract-socket code with `#ifdef __linux__` so the host build compiles.

**Step 4:** Add socket reconnect to the unix sink. If the write fails or the connect is refused, retry the connect every 500 ms from the sink thread, dropping audio meanwhile, and send `H` again after reconnecting. Set `latency_us` from the env var `FAKEPULSE_LATENCY_US` (default 250000).

**Step 5:** Run the harness. Expected: PASS. Commit with "Add fakepulse with host harness".

### Task 3: Runtime bundle and the st15i-fetch helper

**Files:**
- Create: `runtime/build.sh`, `helper/go.mod`, `helper/main.go`, `helper/main_test.go`

**Step 1: Write the failing Go tests.** Using `httptest.NewTLSServer`:
- `fetch(url, out)` writes the file atomically: a `.part` file first, then a rename
- `fetchExtract(url, dir)` unpacks a `.tar.gz` and keeps the exec bits
- a non-200 status returns an error
- `--ca` loads a PEM bundle

**Step 2:** Run `cd helper && go test ./...`. Expected: FAIL.

**Step 3:** Implement `main.go` with the CLI `st15i-fetch [--ca FILE] [--dns a,b] get URL OUT | extract URL DIR`. Reuse the `GLR_DNS`-style resolver override, because Android has no `/etc/resolv.conf`.

**Step 4:** Run `go test ./...`. Expected: PASS.

**Step 5:** Write `runtime/build.sh`. It does the following, putting everything into `build/assets/runtime/`:
- builds the helper: `GOOS=linux GOARCH=arm GOARM=7 CGO_ENABLED=0 go build -ldflags '-s -w'` into `st15i-fetch`
- downloads `libc6_2.41-*_armhf.deb` and `libatomic1_14.*_armhf.deb` from deb.debian.org and extracts the libraries listed in the design
- patches `libc.so.6`, replacing the 17-byte sequence `/etc/resolv.conf\0` with `./resolv.conf\0\0\0\0`, and fails unless exactly 1 replacement happened
- copies `build/native/armhf/libpulse.so.0`
- downloads the Mozilla CA bundle from `https://curl.se/ca/cacert.pem`
- writes `VERSION` (a content hash) so the app can tell when to re-extract

**Step 6:** Run `runtime/build.sh && ls build/assets/runtime`. Expected: all files are present. Commit with "Add runtime bundle and fetch helper".

### Task 4: Audio socket protocol and AudioTrack sink (app)

**Files:**
- Create: `app/src/jp/tkc/st15iplayer/audio/FrameReader.java`, `app/src/jp/tkc/st15iplayer/audio/AudioSink.java`, `test/jp/tkc/st15iplayer/audio/FrameReaderTest.java`, `test/run.sh` (JUnit runner on the host JVM, with `lib/junit-4.13.2.jar`, `lib/hamcrest-core-1.3.jar`, `lib/json-20240303.jar` downloaded by the script)

**Step 1: Write the failing test.** `FrameReader` parses `H`/`P`/`F`/`C` frames from an InputStream, including frames split across reads and zero-length payloads. It calls a `Listener { header(rate, ch); pcm(byte[], off, len); flush(); cork(boolean) }` and throws on an unknown type.

**Step 2:** Run `test/run.sh`. Expected: FAIL.

**Step 3:** Implement `FrameReader`. Its buffer is reused at 64 KiB and grows only when needed.

**Step 4:** Run `test/run.sh`. Expected: PASS.

**Step 5:** Implement `AudioSink`. A thread accepts on `new LocalServerSocket("st15i-player-audio")`, one client at a time. On `H` it creates an `AudioTrack(STREAM_MUSIC, rate, CHANNEL_OUT_STEREO or MONO, ENCODING_PCM_16BIT, max(minBuf*2, rate*ch*2/4), MODE_STREAM)`: twice the minimum, but at least the 250 ms fakepulse reports as latency. Then:
- `P` → `write` (blocking)
- `F` → `pause(); flush(); play()` if it was playing
- `C(1)` → `pause()`
- `C(0)` → `play()`

It requests audio focus with AudioManager and releases it on cork.

**Step 6:** Commit with "Add audio socket sink".

### Task 6: Runtime installer and Soloist process supervisor

**Files:**
- Create: `app/src/jp/tkc/st15iplayer/runtime/RuntimeInstaller.java`, `app/src/jp/tkc/st15iplayer/runtime/SoloistProcess.java`, `app/src/jp/tkc/st15iplayer/Prefs.java`

**Step 1:** `RuntimeInstaller.ensureBundle()` copies `assets/runtime/*` to `filesDir/runtime/` when `VERSION` differs, sets exec permission on `ld-linux-armhf.so.3`, `st15i-fetch` and later on `soloist`, and writes `resolv.conf` from the system DNS servers (`getprop net.dns1` and `net.dns2`, falling back to 8.8.8.8).

**Step 2:** `RuntimeInstaller.ensureSoloist(progress)` runs `st15i-fetch --ca cacert.pem extract https://soloist-builds.spotifycdn.com/soloist_release_arm32.tar.gz filesDir/soloist/` when `soloist` is missing or when it is asked to refresh. It reports progress by reading the helper's stdout lines (`progress N`).

**Step 3:** `SoloistProcess` builds a `ProcessBuilder(ld, "--library-path", runtimeDir, soloistBin, "-n", name, "-k", key, "-D", data, "-C", cache, "-w", "127.0.0.1:8765", "-z", "200")` with:
- working dir `runtime/` (so `./resolv.conf` resolves)
- env `HOME`, `SSL_CERT_FILE`, `FAKEPULSE_OUT=unix:@st15i-player-audio`
- stderr merged

It pumps the logs into a ring of the last 200 lines for a debug view, and exposes `exitCode` callbacks.

**Step 4:** Verify on the device. Build, install, then trigger setup from a temporary debug button that reads the key from a pushed file `/sdcard/soloist_key` (deleted right after) and starts Soloist. Expected: `soloist ctl -w` from the Mac cannot reach 127.0.0.1, but `adb forward tcp:8765 tcp:8765` followed by `soloist ctl -w 127.0.0.1:8765 status` shows `logged in`.

**Step 5:** Commit with "Add runtime installer and Soloist supervisor".

### Task 7: PlayerService

**Files:**
- Create: `app/src/jp/tkc/st15iplayer/PlayerService.java`, `app/src/jp/tkc/st15iplayer/BootReceiver.java`
- Modify: `app/AndroidManifest.xml`

**Step 1:** Implement a foreground service that holds a MulticastLock, a `WifiLock(WIFI_MODE_FULL_HIGH_PERF)` and a `PARTIAL_WAKE_LOCK` while Soloist runs. It owns `AudioSink`, `SoloistProcess` and `SoloistClient`, with the following rules:
- **Restart backoff:** 1, 2, 4 … 60 s.
- **Exit code 10:** run `ensureSoloist(refresh=true)`, then restart.
- **Wi-Fi changes:** a `CONNECTIVITY_ACTION` receiver restarts Soloist when Wi-Fi comes back.
- **Notification:** title and artist, plus `PendingIntent` actions prev / play-pause / next routed to `SoloistClient`.
- **Media buttons:** a `RemoteControlClient` with a media button receiver (API 14+) handles headset play/pause.

**Step 2:** `BootReceiver` starts the service if `Prefs.autoStart`.

**Step 3:** On the device, start the service, select "ST15i" from the phone, and play. Expected: **audio comes out of the ST15i speaker**, and the notification shows the track.

**Step 4:** Commit with "Add PlayerService".
