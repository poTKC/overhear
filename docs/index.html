Overhear

古い Android 端末を、
Spotify Connect のスピーカーに。

スマホの Spotify で再生先にこの端末を選ぶと、端末から音が出て、画面に曲名・アートワーク・シークバー・キューが表示されます。端末の画面から自分のライブラリをたどって選曲することもできます。

Overhear とは

Overhear は、引き出しに眠っている古い Android 端末を Spotify Connect のスピーカー兼再生画面にするアプリです。音を鳴らすのは Spotify 公式のヘッドレスクライアント Soloist で、Overhear はそれを端末の上で動かします。非公式クライアントは使わず、DRM の回避もしません。

スピーカーとして

スマホや PC の Spotify から再生先に選ぶだけ。曲名・アートワーク・キューが表示され、端末からも再生・一時停止・曲送りができます。音量は端末の音量キーとスマホの Spotify の両方で変えられ、連動します。必要なのは Soloist の API キーだけです。

ライブラリ（任意）

Spotify にログインすると、端末の画面で検索・お気に入りの曲・プレイリスト・アルバム・アーティスト・最近再生をたどれます。順番どおり・シャッフルの再生、選んだ曲からの再生、お気に入りへの追加・削除もできます。自分の Spotify Developer アプリの Client ID が要ります。

必要なもの

  • Android 4.1 以降（minSdk 16）の ARMv7 端末。Wi-Fi につながること。
  • Spotify Premium のアカウント（Soloist の API キーの発行に必要）。
  • 端末と同じ Wi-Fi につながるスマホ（初回の設定とログインに使います）。
  • APK を端末へ移すための PC か、もう一台のスマホ。

動作確認は Xperia mini（ST15i、Android 4.3）だけです。 ほかの端末でも動く見込みはありますが、確かめていません。

インストール

古い Android のブラウザは、いまの GitHub の TLS に対応していないため、端末から直接ダウンロードできません。PC かスマホで APK をダウンロードしてから、端末へ移してください。

  1. overhear.apk を PC かスマホでダウンロードします。
  2. 次のどちらかで端末に入れます。
    • USB でコピー: 端末の設定の「セキュリティ」で「提供元不明のアプリ」を許可し、APK を端末にコピーしてファイルマネージャーで開きます。
    • adb: USB デバッグを有効にして、PC から次を実行します。
adb install -r overhear.apk

更新は上書きインストールで。 同じ署名の APK を上から入れれば（-r）、API キーとログイン状態は残ります。アンインストールすると、保存した API キーと Spotify のログインも消えます。署名の違う APK は上書きできません。

初回セットアップ

API キーや Client ID は端末では入力しません。端末に QR コードを出し、同じ Wi-Fi のスマホで入力します。

  1. Soloist の API キーを発行する

    developer.spotify.com/dashboard/soloist で、自分の Spotify Premium アカウントの Soloist API キーを発行します。

  2. Spotify のアプリを作る ライブラリを使うときだけ

    ライブラリは Spotify Web API を使うので、自分の Spotify Developer のアプリが必要です（Overhear には Client ID が組み込まれていません）。スピーカーとしてだけ使うなら、この手順は飛ばしてかまいません。

    1. developer.spotify.com/dashboard でアプリを作り、Web API を有効にします。
    2. Redirect URI に次を登録します（末尾のスラッシュまで含めます）。 https://potkc.github.io/overhear-auth/callback/
    3. アプリの Settings に出る Client ID（32 文字の16進数）を控えます。

    開発モードの制約: アプリの所有者が Spotify Premium であること、使えるのは User Management の許可リストに登録した最大 5 人までです。自分以外の人が同じアプリでログインするときは、その人の Spotify のメールアドレスを User Management に登録してください。

  3. 端末で「スマホで認証」する

    1. 端末で Overhear を開きます。API キーがまだないので設定画面が開きます。
    2. 「アカウント」の 「スマホで認証」 を押すと、QR コードが表示されます。
    3. 端末と同じ Wi-Fi につないだスマホで QR コードを読み取ります。
    4. 開いたページに Soloist API キーと Client ID を貼り付け、「保存してログイン」 を押します。続けて Spotify のログインと許可の画面が開くので、許可します。
    5. 端末の画面が「完了」に変わります。

    ライブラリを使わないなら、Client ID は空欄のまま「Spotify にログインする」の印を外して 「保存」 を押します。QR コードの画面は最大 5 分で閉じ、QR コードは一回限りです。

  4. 「保存して開始」

    設定画面に戻り、「再生」でデバイス名（既定は端末の機種名）を決め、必要なら「起動時・アプリを開いたときに自動で開始」を選んで 「保存して開始」 を押します。初回はランタイムの展開と Soloist のダウンロード（約 12 MB、Spotify から直接）が行われ、終わると再生画面に移ります。

  5. スマホの Spotify で再生先に選ぶ

    スマホの Spotify で再生先（デバイス）の一覧を開き、そのデバイス名を選びます。端末から音が出れば完了です。

使い方のメモ

しばらく使わないと止まります（自動停止）
この端末で再生していない状態（一時停止中・Standby・接続待ちなど）が続くと、電池を守るためにサービスを止めます。時間は設定画面の「再生」の「再生していないときの自動停止」で選べます（既定 15 分。5 分・30 分・しない）。再生画面かライブラリを表示している間は数えません。
止まったあとに再開するには
アプリ（再生画面かライブラリ）を開くと、自動停止のあとは再び開始します。止まっている間はアートワークの位置に大きな電源ボタンが出るので、それをタップしても開始できます（左下の Stopped — tap to start も同じ）。通知の ✕ や設定の「停止」で止めたときは、開いても自動では開始しません。
Standby と出ているとき
この端末がいまの再生先ではない状態です（ほかの端末に再生を移したあとなど）。最後の曲が表示されていれば、▶ を押すとその曲をこの端末で再生し直します。
6 か月ごとにログインし直す
開発モードの Spotify アプリでは、ログインが最初の認可から 6 か月で切れます。ライブラリに「Spotify のログインが切れました — タップしてスマホで認証」と出たら、「スマホで認証」を開き、入力欄は両方空欄のまま「保存してログイン」を押してください。
音量
端末の音量キーでメディア音量を変えます。スマホの Spotify で音量を変えても、端末のメディア音量が連動します。

キーとログインの扱い

  • Soloist API キー・Client ID・Spotify のログイン情報は端末の中にだけ保存されます。Overhear には開発者のサーバーがなく、キーやトークンは Spotify 以外へは送られません。
  • 「スマホで認証」の間、端末は Wi-Fi のアドレスで最大 5 分だけ待ち受けます。QR コードの一回限りの値がないアクセスは拒否します。
  • Redirect URI の中継ページ（potkc.github.io/overhear-auth）は、Spotify のログインの結果を LAN 内の端末へ転送するだけの静的なページです。転送先はプライベート IPv4 のアドレスに限ります。ソースは poTKC/overhear-auth で公開しています。
  • Soloist は APK に含まれていません。端末上で Spotify の CDN から直接ダウンロードします。
